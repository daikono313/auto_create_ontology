# 0004. LLM は Claude Code のヘッドレスモードで呼ぶ

- ステータス: 承認
- 日付: 2026-10-23

## コンテキスト

概念と関係の抽出にはLLMを使う。ただし Claude API（APIキー）は使えない。
Claude Code はサブスクリプションのログインで使える。

調べた結果、環境変数 `ANTHROPIC_API_KEY`（残高なし）が設定されていると、それがログインより優先され、
`Credit balance is too low` で失敗することが分かった。

## 決定

- `claude -p --output-format json --json-schema <schema> --tools ""` を子プロセスで呼ぶ（`ontogen/llm.py`）。
  - `--json-schema` には Pydantic モデルから生成したスキーマを渡す。結果の `structured_output` を検証して使う。
  - `--tools ""` でツールを無効にし、ファイル操作などをさせずに、入力テキストから JSON を返すだけにする。
- 子プロセスに渡す環境変数からは `ANTHROPIC_API_KEY` を取り除く。
- プロジェクトの CLAUDE.md などを読み込ませないよう、一時ディレクトリを作業ディレクトリにして実行する。
- 応答は「プロンプト + スキーマ + モデル」のハッシュでキャッシュする（`<out>/llm_cache/`）。

## 検討した代替案

- Claude API の SDK を使う: APIキーが使えないため不可
- Claude Agent SDK: 認証にAPIキーが前提となる場面がある。また、今回の用途（単発の構造化出力）にはエージェント機能は不要
- Claude Code の対話セッションで、人がプロンプトを入力して実行する: 再現性がなく、評価やバッチ処理ができない

## 結果

- APIキーなしで、構造化出力をパイプラインに組み込める。
- サブスクの利用上限を消費する。ページパターン数 + 1 回の呼び出しが発生する。
- 将来 API が使えるようになったら、`llm.py` の `call_structured` を差し替えるだけで移行できる（呼び出し側は変更不要）。
- CLI のバージョンアップでオプションや出力形式が変わるリスクがある。
