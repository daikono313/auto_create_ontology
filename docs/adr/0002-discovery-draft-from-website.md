# 0002. Webサイトを入力に、ディスカバリー用の叩き台を出力する

- ステータス: 承認
- 日付: 2026-10-23

## コンテキスト

データ基盤のオントロジー設計（Palantir Foundry でいう Object / Property / Link / Action）で一番手間がかかるのは、
初期のドメイン理解と用語の洗い出しである。顧客のWebサイトには、商品・サービス・顧客区分・拠点などの
ビジネス用語がまとまっている。

ただしWebサイトに載っているのは顧客向けの情報なので、次のものは分からない。

- 社内の業務オブジェクト（受注・在庫・案件など）
- データ上のキーや粒度、ソースシステム
- 業務ルールや状態遷移（Action の大半）

また、現時点では顧客の実データ（DBスキーマなど）にアクセスする想定はない。

## 決定

- 成果物は **初回ヒアリング前に使う叩き台（仮説）** と位置づける。完成したオントロジーは目指さない。
- サイトから判断できないことは、無理に埋めず `open_questions`（ヒアリング事項）として出す。
- 画面にないが推定できる概念（例: 「Add to basket」ボタンから Basket を推定する）は、【推定】と明記して含める。
- 全自動は目指さず、「8割を自動で作り、人がレビューして直す」ことを前提に出力を設計する。

## 検討した代替案

- 実装にそのまま使えるオントロジーを生成する: 実データがないので正しいか確かめられず、読んだ人に正しいと思い込ませてしまう
- 社内資料やDBスキーマも入力にする: 現時点では入手できないため対象外。将来の拡張候補とする

## 結果

- 評価軸は「正確さ」に加えて「ヒアリングで役立つか（論点の網羅性）」になる。
- `open_questions` にどれだけ具体的な質問を出せるかも、成果物の良し悪しを左右する。
- 実データとの対応付けは、このツールでは扱わない。
