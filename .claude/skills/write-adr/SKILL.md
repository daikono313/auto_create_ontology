# ADR の作成

## いつ書くか

- 技術選定や方式の変更（LLM の呼び方、クロール方式、出力形式など）
- `ontogen/schema.py` の変更（LLM キャッシュ・gold・評価に影響するため）
- 既存の ADR と矛盾する変更をするとき（新しい ADR を書き、古いものを置換する）

小さなバグ修正やリファクタリングには書かない。

## 手順

1. `docs/adr/README.md` の索引を見て、次の番号を決める。関連する既存 ADR を読む。
2. `docs/adr/template.md` をコピーして `docs/adr/NNNN-kebab-case-title.md` を作る。
3. 各節を書く。
   - **コンテキスト**: 何が問題で、どんな制約があったか。実際に観測した事実（エラーメッセージ、評価の数値）があれば書く
   - **決定**: 何をするか。関連するファイルや関数名を書く
   - **検討した代替案**: 却下した案と、その理由。これがないと後で同じ議論を繰り返す
   - **結果**: 得たもの、諦めたもの、新しく生まれた課題
4. ステータスは、ユーザーと合意済みなら `承認`、そうでなければ `提案` にする。
5. `docs/adr/README.md` の索引に1行追加する。
6. 既存の ADR を置き換える場合は、古い ADR のステータスを `置換（→ NNNN）` に変える（本文は書き換えない）。
