# 0012. クロールの範囲を開始URLのパス以下に絞り、スラッグ形式のURLもパターンにまとめる

- ステータス: 承認
- 日付: 2026-10-23

## コンテキスト

webscraper.io のテスト用ECサイト（ADR 0011）は `/test-sites/e-commerce/allinone` の下にあり、同じホストに
料金ページやブログもある。これまでのクローラーはホスト全体を辿るので、関係のないページまで取得してしまう。

また、ADR 0006 の方式では、数字を含むパスセグメントだけを `*` にしていた。Shopify の `/products/<スラッグ>` や
WooCommerce の `/shop/<スラッグ>/` は数字を含まないので、商品ごとに別のパターンになり、
パターンごとの上限で取得数を抑えられず、LLM の呼び出しも商品の数だけ増える。

## 決定

- クロールの範囲は、開始URLのパス以下にする（開始URLがファイル名で終わるならそのディレクトリ以下）。
  `--scope` で変えられる（`crawl.default_scope`）。
- リンクのクエリ文字列とフラグメントは除く。並べ替え・絞り込み・バリエーション指定（`?variant=`）の URL を同じページとみなす。
- クロール中に、親パスごとに見つかった子のセグメントを数える。子が5種類以上ある親の下では、最後のセグメントも `*` にする
  （`crawl.url_pattern`、`SIBLING_THRESHOLD`）。トップ直下のセグメント（`/products` や `/pages`）はまとめない。

## 検討した代替案

- 商品・コレクションのパス名（`products`、`collections`、`shop`）を決め打ちする: プラットフォームごとに名前が違い、
  日本語サイトや独自の構成に対応できない
- DOM 構造でテンプレートを判定する: ADR 0006 と同じく、実装の手間が大きいので見送る

## 結果

- scrapeme.live の一覧ページにあったリンクで試すと、商品のURLが `/shop/*/` の1パターンにまとまった。
- 子の数はクロールの途中で増えるので、同じURLでも早い段階では個別のパターン、後ではまとめたパターンとして数えられることがある。
  取得数が上限より少し増えることはあるが、実害は小さいと判断した。
- `/pages/about` と `/pages/faq` のように、テンプレートは同じでも内容の違うページも、5種類以上あれば1パターンにまとまる。
- クエリ文字列でページを切り替えるサイト（`?id=123` だけで商品を区別するなど）は、すべて同じページとみなしてしまう。
