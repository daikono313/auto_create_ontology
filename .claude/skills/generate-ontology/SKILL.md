# オントロジー叩き台の生成

背景: `docs/adr/0002`（叩き台という位置づけ）、`0003`（対象サイトの方針）、`0006`（生成方式）。

## 手順

1. クロールしてよいか確認する（ADR 0003）
   - `https://<host>/robots.txt` を取得し、対象のパスが Disallow されていないか確認する
   - 利用規約でスクレイピングが禁止されていないか確認する。判断できなければユーザーに確認してから進める
   - Amazon など、規約でスクレイピングを禁止しているサイトは実行しない

2. 出力先を決める: `out/<サイト名の短いスラッグ>`（例: `out/allbirds`）

3. 実行する（LLM の呼び出しがパターン数 + 1 回あり、数分かかるので timeout は長めにとる）
   ```bash
   uv run ontogen run <URL> --out out/<slug> [--gold gold/<slug>.yaml]
   ```
   - 正解データがあれば `--gold` を付ける
   - 主なオプション: `--max-pages`（既定40）、`--per-pattern`（既定3）、`--recrawl`（クロールを取り直す）

4. クロール結果を確認する: ログのパターン一覧を見て、主要なページ種別（商品・一覧・カートなど）を取得できているか確認する。
   商品ページが大量のパターンに分かれている、または別の種類のページと同じパターンにまとめられている場合は、URLパターン判定
   （`ontogen/crawl.py` の `url_pattern`）がサイトに合っていない。ADR 0006 の「結果」を参照する。

5. レポートをレビューする: `out/<slug>/report.md` を読み、次の点を確認する
   - 根拠の照合で不一致がないか。不一致があれば、LLM の捏造なのか前処理の問題なのかを `pages.json` と見比べて判断する
   - UI 要素（ページ、メニュー、ページ送り）が Object Type になっていないか
   - 【推定】の要素が妥当か
   - ヒアリング事項が具体的か

6. ユーザーに報告する: 主な Object Type と関係、注目すべき推定、主なヒアリング事項、気になった品質の問題を短くまとめる。
   レポートの全文は貼らず、`out/<slug>/report.md` を案内する。

## 注意

- `ANTHROPIC_API_KEY` があっても、`ontogen/llm.py` が子プロセスから取り除くので問題ない（ADR 0004）
- プロンプトや前処理を変えたときは、変更前後で `evaluate-ontology` スキルを使って比較する
