# オントロジーの評価

背景: `docs/adr/0008-evaluation-against-gold.md`。

## 単発の評価

```bash
uv run ontogen eval out/<slug>/ontology.yaml gold/<slug>.yaml
```

## 変更の前後を比べる

LLM の出力は実行ごとに揺れるので（ADR 0008）、1回ずつの比較で結論を出さない。

1. 変更前と変更後で、それぞれ3回以上実行する。出力先は実行ごとに分ける（例: `out/<slug>-before-1`）。
   - LLM の応答はキャッシュされる（`<out>/llm_cache/`）。出力先を分ければ別の実行になる
   - クロールは取り直さなくてよい。`pages.json` を新しい出力先にコピーしておけば再利用される
2. 各実行を `ontogen eval` にかけ、Object / Property / Link / Action の適合率・再現率の平均と、ばらつきを出す。
3. 平均の差がばらつきより小さければ、「差があるとは言えない」と報告する。

## 結果の読み方

- extra（余分）に出た要素は、生成の誤りか正解の漏れかを判断する。妥当な推定なら、gold に `optional` として足すことをユーザーに提案する
  （黙って gold を書き換えない。点数を上げるために正解を変えるのは本末転倒なので、必ず理由を添える）。
- missing（不足）に出た要素は、前処理で値が欠けていないか（`pages.json` の digest にその値があるか）を先に確認する。
  初回に星評価を取りこぼしたのは、値が class 属性にしかなかったため（ADR 0006）。
- inferred に出た要素は、ジャーニーを補うために推定したもの。適合率には入らないので、妥当かどうかはレポートを読んで判断する（ADR 0009）。
- 評価は `open_questions`、ジャーニー、状態遷移の質を見ていない。必要ならレポートを読んで定性的にコメントする。

## 報告

表で、変更前と変更後の平均（± ばらつき）を示し、どの変更で数値が上がったか、または変わらなかったかを短くまとめる。
