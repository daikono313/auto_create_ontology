# 0013. 推定かどうかを inferred 項目で持ち、ジャーニーは確認できた起点の先だけを補う

- ステータス: 承認
- 日付: 2026-10-23

## コンテキスト

ADR 0009 では、推定した要素は説明文の先頭に【推定】と書くことにしていた。評価でも、この書き方と
「根拠がないこと」を手がかりに推定の要素を判定していた。

webscraper.io のテスト用ECサイト（ADR 0011）で生成したところ、次の2つが起きた。

- LLM は Cart や Order を「推定オブジェクト」と書いたが、先頭が【推定】ではなかった。
  さらに商品画像のファイル名（`cart2.png`）を引用して根拠にしていたので、評価で推定と判定されなかった。
- サイトに「Items listed here are not for sale.」と書いてあり、カートのボタンもないのに、
  ECの典型的な流れとしてカートから注文までを補っていた。プロンプトが、確認できないステップを典型的な流れで補うよう指示していたためである。

## 決定

- Object・Link・Action に `inferred`（推定なら true）を必須の項目として加える。評価・画面・レポートはこの項目で推定を判断する。
- 推定の要素に、ファイル名や CSS クラスのような弱い引用を付けて、確認済みに見せないようプロンプトで指示する。
  根拠を必須にするのは、確認済み（`inferred: false`）の要素だけにする。
- ジャーニーを確認できた範囲より先に補うのは、サイトにその流れの起点があるときだけにする
  （「Add to cart」のボタンがあれば、カートと購入手続きを補ってよい）。起点がない、または販売していないと書かれている場合は、
  流れを作らず `open_questions` で確認する。

## 検討した代替案

- 【推定】の書き方をプロンプトでさらに強く指示する: 文字列の書き方に頼る点は変わらず、また崩れる
- ジャーニーをサイトで確認できたステップだけにする: books.toscrape.com のように、カートのボタンがあって購入以降が見えないサイトで、
  ヒアリングの叩き台として役立つ推定がなくなる

## 結果

- webscraper.io では、カートと注文を作らず、閲覧から容量の選択までのジャーニーになった。
  カートやログインの機能が本当にないかは、ヒアリング事項に入った。評価は Object・Link・Action とも適合率・再現率が 1.0 になった。
- books.toscrape.com では、カートのボタンを起点に、購入までの推定が引き続き出力された。
- スキーマが変わったため、以前に出力した `ontology.yaml` は `ontogen eval` で読めなくなった。生成し直す必要がある。
